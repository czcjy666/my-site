落地验证形态

把 Agent 落进生产流程

企业评估 AI 只看两件事：能不能提效、能不能比现在便宜。项目以工厂设备运维为首个场景， 打通「AI 助手 · ERP 工单 · 钉钉审批」三系统链路——排故、查件、提单、审批、受理，一次对话走完。

  • 1398可核验 chunk
  • 0.852Recall@5 基线
  • 60条黄金评测集
  • 3个系统打通
01

定位

设备报故障时，现场要经历：翻手册判断故障码含义、到 ERP 查这台设备的台账号、问仓库备件有没有货、 填一张维修工单、再找人走审批。四步以上人工切换，跨三个系统，信息散在不同人手里。

项目把这条链路收进一次对话：Agent 自己决定查手册还是查库存、自己组装工单草稿， 关键动作交回人工确认，审批走企业既有的钉钉流程，通过后自动落到 ERP 受理。 不新建系统、不改企业流程，是往已有系统上接。

手册排故 → 定位台账 → 核对备件 → 起草工单 → 钉钉审批 → ERP 受理

原本 3 个系统、4 步以上人工操作；现在 1 次对话，人工只做确认与同意。

功能

九块内容，每块一个问题、一段做法、几行可核验的细节。

F1RAG 语料工程

表格嵌套图片、表格嵌套表格、图文交错——这些版式用固定长度切分会把参数表切碎， 检索出来答非所问。做法是按四类形态分别定制结构化切分口径，全程 Markdown 正文， 图片裁切后嵌入 OSS，并做字符级原文核对与数量对账。

  • 交付 1398 个 chunk：参数 1207 · 警告 91 · 故障 100
  • 四类形态：带图 57 · 嵌套表格 86 · 嵌套带图 2 · 普通 1062
  • 950 条参数 ⇄ 故障交叉引用，供检索层做展开

F2检索层

现场工人问的是大白话：「一减速就报过压」。精确工具按「编号 → 参数组前缀 → 名称 → 模糊」 四级回退，语义工具走向量召回；两个工具返回同构载荷、正文不裁剪，选哪条路交给 Agent。 交叉引用把两者串成闭环：查到故障，展开它引用的参数。

  • bge-m3 1024 维 · HNSW 余弦索引 · 共 4 个索引
  • 单次检索 P50 ≈ 1.05s（embedding 725ms + 库内 330ms）
  • 只命中场景绑定的知识库，实测跨库查询为空

F3引用溯源

回答里引用检索结果的事实（参数值、故障原因、措施）时标注来源编号，编号按本轮命中顺序递增， 多路检索合并编号。hover 看摘要，点开看来源列表——回答有依据，才谈得上敢用。

  • 检索层不裁剪正文，只在最终拼 prompt 处统一处理
  • 没有检索依据的内容不标注编号，也不编造编号

F4评测体系

先跑一次裸向量基线并留档，此后任何改动都与它逐题 diff——「从 X 到 Y」的 X 必须先存在。 拒答阈值不是拍出来的：用 5 条负例的分数分布，卡在负例最高分与正例最低分之间。

  • 60 条黄金集 · 5 类题型 · 24 条口语化问法 · 9 组对照题
  • Recall@5 0.852 · Hit@5 0.927 · MRR 0.809
  • 拒答阈值 0.62（负例最高 0.599 < 阈值 < 正例最低 0.648）
  • 知识库重构迁移后指标逐位一致，无回退

F5Agent 编排

思考过程、正文、工具参数都是增量输出；随时可以停止生成，已产出的内容照常保留。 关键动作不靠提示词约束，而是图结构：起草工单后强制挂起等待人工决定， 批准之前受理接口在工具节点被硬拦——模型绕不过去。

  • SSE 十类事件，覆盖思考 / 正文 / 工具 / 来源 / 耗时 / 确认
  • 起草 → 挂起 → 人工批准；被拒则工单保持草稿
  • 每轮思考、token、耗时落库，会话级汇总

F6对接 ERP

自托管 ERPNext 作为工单系统，用最小权限账号的 token 接入，只暴露 4 个业务动作 （资产台账 / 备件库存 / 起草工单 / 受理工单），不提供通用 CRUD——把通用写接口交给大模型， 等于把生产库交给它。写入先建 On Hold 草稿，人工确认后才置 Open。

  • 限流与 5xx 指数退避重试；字段不兼容时自动降级
  • ERP 错误响应提取成人话，直接回给用户
  • 9 容器自托管，无商业 ERP 授权与订阅

F7对接钉钉

扫码登录打通身份链路，审批模板按名幂等复用，审批人由服务端跨部门规则路由——提交人不可自选。 提交后立即返回，后台 30 秒轮询跟进，审批通过自动受理 ERP 工单， 人只需要在钉钉点一次同意，不用二次录入。

  • 现场照片走 OSS 直链；附件写入审批钉盘
  • 网页端先行处理时终止钉钉审批单，保持单一事实来源
  • 钉钉不可用时自动降级为网页确认，不阻塞工单

F8Skill 架构

没有把工具一股脑塞进提示词。系统提示词只注入技能索引，模型需要执行某个工作流时， 先调用 load_skill 读取正文，该技能勾选的工具才挂载进工具表。常驻工具只有 3 个， 接新场景不会让每轮的 token 和响应成本往上走。

  • SKILL.md + scripts 约定，不引入 MCP，改文件即热加载
  • 脚本走 stdin / stdout JSON，超时、截断、异常统一兜底
  • 单个技能文件损坏只标红跳过，不拖垮 Agent

F9管理后台

文档上传即解析（PDF / DOCX / MD / TXT），解析失败可重来，片段编辑后自动标记向量过期并可单独重嵌。 权限是细颗粒的：资源 × 动作 × 知识库范围，授权与撤销全部留痕。 改模型、开 rerank、换审批人规则都在界面里点，不用改代码、不用发版。

  • 九类模块：知识库 / 文档 / 片段 / 场景 / 权限 / 工具 / 技能 / 评测 / 配置
  • 无权限访问后台自动弹回，越权接口返回 403
  • 授权操作与审批记录入库，可回溯
